# Documentation Targets

Canonical pages live under workspace-root `docs/`:

- `docs/getting-started.md` — prerequisites, setup, and first run.
- `docs/architecture.md` — service boundaries, layering, shared infrastructure, and request flow.
- `docs/configuration.md` — settings, environment overrides, and secret references.
- `docs/messaging.md` — provider selection, contracts, transport, inbox/outbox, and retries.
- `docs/multi-tenancy.md` — tenant resolution, isolation, shared and dedicated databases.
- `docs/security.md` — authentication, authorization, permissions, secret handling, and hardening.
- `docs/deployment.md` — images, charts, environments, promotion tooling, and rollout safety.
- `docs/testing.md` — test taxonomy, commands, fixtures, and verification scope.
- `docs/adding-a-service.md` — service shape, registration, persistence, chart, and tests.
- `docs/troubleshooting.md` — symptom-driven diagnosis and recovery.
- `docs/task/README.md` — task-record policy.
- `docs/task/pending-implementation/` and `docs/task/done-implementation/` — durable plans and completion records.

Add or update a section in the closest page. Create a new top-level page only when the topic has a distinct audience and cannot remain navigable as a section.
